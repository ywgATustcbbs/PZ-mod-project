# RailroaderRV test server scripts

- `run_test.py` stages the local `RailroaderRV` and `BuildingCraft` mods, starts the server using the selected cache's profile, and launches the visible server console plus the regular game client.
- Select `--railroader-build workshop` (the default) for the Workshop release, or `--railroader-build preview` for the local preview package. Workshop mode defaults to `Z:\RailroaderRVCache\server` and `client`; preview mode defaults to `testserver/runtime/preview/server` and `client`. The caches keep each mode's server INI, local mods, saves, logs, and client mod search roots apart.
- In preview mode, the launcher copies the read-only source `Railroader-prerelease/railroader_pz_mod` to each selected cache's `mods/railroader_pz_mod`, matching the local-mod layout in `READ_ME_FIRST.txt` under the active `-cachedir`. The server profile lists `Railroader` in `Mods` and omits its Workshop ID, so the server gets that mod from the staged local preview package without moving or changing any Workshop files.
- The client receives `-modfolders mods,workshop,steam`; the game parses that order and chooses the first matching mod ID, so the local preview package in its selected cache takes priority over the installed Workshop copy. The launcher does not change the client Steam Workshop package.
- The launcher updates only `Mods` and `WorkshopItems` in the selected cache's `Server/test.ini`, preserving other options. On first use, it copies `testserver/runtime/server/Server/test.ini` as a profile seed when available; it copies only this INI, never saves or other cache data. Workshop mode uses `Mods=BuildingCraft;Railroader;RailroaderRV;B42Trans_CN` and `WorkshopItems=3556544454;3774360904`; preview mode uses the same mod list and `WorkshopItems=3556544454`. If no profile seed exists, Project Zomboid's `ServerOptions` writes its complete defaults on first server startup. The launcher does not modify `test_SandboxVars.lua`.
- Each process receives its cache through `-cachedir`; saves, logs, settings, and staged mods therefore stay with the selected mode.
- The launcher initializes only the default Workshop client RAM disk cache. Workshop mode copies `testserver/runtime/client` on first use when the Z: destination does not exist. Preview mode uses `testserver/runtime/preview` directly and does not read or write the RAM disk cache layout marker. The Workshop marker records Z: cache locations; an ambiguous cache or missing registered Z: client cache stops Workshop startup instead of merging or recreating from a potentially stale copy.
- Preview instance state is stored in `testserver/runtime/preview/.railroader-rv-test-instance.json`; Workshop instance state remains in `testserver/runtime/.railroader-rv-test-instance.json`. The launcher lock stays at the shared runtime root to prevent two local tests from claiming the same server ports.
- Workshop Z: caches and their saves/logs are not copied back or automatically deleted. They survive launcher runs while the RAM disk contents survive; a volatile RAM disk reset can lose them. Preview saves/logs remain in `testserver/runtime/preview`. Users manage Z: capacity and preserve any needed Workshop data before clearing it.
- The persistent server cache retains its saves, player database and admin permissions between runs; the launcher does not automatically reset that data.
- The Windows launcher selects the UTF-8 console code page and Java file encoding for startup output.
- `--client-cache` and `--server-cache` override the defaults. Workshop mode uses each supplied path directly; preview mode treats each supplied path as a base and appends `preview`. Keep custom cache bases independent by mode; do not point a mode at the other mode's default cache or deliberately cross the resulting cache paths. Maintain other server options and SandboxVars files in the selected server cache. The one-click runtime test remains `python testserver/run_test.py` from the project root; use `--railroader-build preview` to select the preview build, and do not start a separate server or client for runtime verification.
