# RailroaderRV 1.0 server Lua

- Core/ is the server event, command, dispatch, and Railroader adapter layer. Common/ owns server world and persistence helpers plus the single Lua schema constant. RVMapping/ owns stable per-unit mappings and Railroader entry/exit.
- Construction/ owns server-side generation validation, staging, area preparation, object building, relocation phases, and mapping commit. Its generation transaction record is process-local; the transaction has no persistent rollback ledger. VehicleTransport/ has two conditional failure side-effect boundaries documented in the project module-analysis notes; do not describe them as reproduced runtime failures.
- BoundaryGuard/ enforces authoritative RV bounds and transition state. DemolitionProtection/ attributes shell walls. TemplateRecovery/ repairs protected template objects. RoomOwnership/ handles ownership checks. RoofRefresh/ recalculates room and roof metadata. WallReloadProtection/ coordinates the separate exterior-wall reload flow.
- Power/, Water/, and Roof/ own the server utility services. Safehouse/ owns native safehouse claims. VehicleTransport/ saves and restores transport state; CarVisual/ handles server flatcar requests and cargo manifests. Items/ owns item distribution hooks. TemplateDevelopment/ handles the retained developer commands.
- The template development client entry defaults off through C.ENABLE_TEMPLATE_DEVELOPMENT. If enabled, the server still checks UseDebugContextMenu before accepting a request.
- The server is the only authority for world changes and network snapshots. Validate the sender, capability, range, target region, current server state, and transaction phase before acting; clients send intent rather than trusted coordinates or world state.
- ModData, templates, mappings, utility records, and process-local module state are trusted according to the current schema and interfaces. The startup schema check runs once and only warns on a missing or mismatched value. Do not add repeated structure checks, fallback values, reconciliation, migration, or cross-module interface guards; let impossible internal states raise normal game exceptions.
- Project Zomboid provides reliable ordered network delivery. Do not add a retry, duplicate, or ordering protocol. Use an ACK or timeout only when a later server step depends on a client-side asynchronous action.
