# RailroaderRV client Lua

- `RV_ContextMenu*.lua` and `RV_RailroaderContextMenu.lua` own client menus, input hooks, local presentation, and intent-only requests to the server.
- Client command handlers consume server-selected identities, bounds, snapshots, and acknowledgements. Client state is presentation/handshake state; server validation remains authoritative for permissions and world changes.
- `RV_BoundaryClient.lua` applies identity-scoped corrections sent by the server. `RV_UtilityClient.lua` handles local utility visibility and connection/display state.
- `RV_ContextMenu_RoomOwnership.lua` checks each local player's current square every tick. It schedules a full bounds scan only after a local stale-reference/error hit, a relevant object event, or the initial refresh transaction. Persistent local API errors are edge-triggered until a successful check, and object-event bursts are coalesced by a cooldown with bounded delayed rechecks. A full scan reports incomplete if any base structure square or captured roof-object host is not loaded.
- `RV_ContextMenu_Relocation.lua` gates final relocation on the selected target square loading, then runs bounded transaction pre/post scans. It does not repeat a full scan on every tick while the target streams in, and it sends no final ACK without complete coverage and coordinate/room checks. An incomplete scan or latched current-square API error blocks the transaction; at most one later matching repair trigger can open one fresh bounded scan window per transaction phase.
- Keep iteration compatible with the game Lua runtime. `RV_BoundaryClient.lua` uses `pairs()` to remove matching snapshots because the tested Kahlua environment does not provide the global `next` function.
- TEMPORARY `[RailroaderRVTest][PerfTrace]` summaries in `RV_ContextMenu_RoomOwnership.lua` emit about once per aligned 10-second window, labeled with Unix epoch seconds from protected `os.time()` calls. If that clock is unavailable at module load or errors later, tracing is disabled. Roomguard full-scan timing uses protected `getTimestampMs()` calls only; remove these counters after CPU correlation is complete.
