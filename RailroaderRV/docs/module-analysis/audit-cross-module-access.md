> **状态（RailroaderRV 1.0）**：本文件是静态审计记录；其行号、计数和源码结论并非本次发布的全量重核，也不是运行时验证。当前实现以 [源码](../../contents/mods/RailroaderRV/42/) 与 [README](../../README.md) 为准，项目约束以 [agents.md](../../../agents.md) 为准。历史建议不构成修复授权，采纳前须按现行约束重新取证。

## 审计范围与方法

- **事务边界**：只读分析。本报告是本次事务的唯一写入文件；未修改任何 `.lua` 源码、配置或测试文件；未运行游戏、服务器、Lua 解释器或 `python testserver/run_test.py`（本工作目录下也不存在 `testserver/`）。所有行号来自本次实际读取。
- **范围**：`contents/mods/RailroaderRV/42/media/lua/` 全树 65 个 Lua 文件（client 11 / server 47 / shared 11 + 2 个 `agent.md`）。重点通读了 server 侧 Core、Construction、BoundaryGuard、DemolitionProtection、RVMapping、RoomOwnership、TemplateRecovery、WallReloadProtection、Power、Water、Common 的代表文件全文或关键区段，以及 client `GUI/` 全部文件。
- **"包"的判定口径**：以**组合根**（谁创建 ctx、模块把导出写回哪个命名空间）为准，物理目录作为辅助事实。理由：`BoundaryGuard/RV_RailroaderServer_BoundaryValidation.lua` 与 Boundary 服务同目录，但由 `RVMapping/RV_RailroaderServer_Mapping.lua:150-167` 用另一个 ctx 装载、导出到 `Adapter` 命名空间，共享 `_states` 的两侧装载上下文不同（见跨-3），故按跨模块统计并注明其物理位置。
- **检索模式（ripgrep，`media/lua` 全树）**：

- **未运行运行时验证**：本报告全部结论为静态源码事实或标注了触发条件的条件性推断；`tests/test_rv_server.py` 与当前源码多处不一致（见"接口缺口与静态发现"第 6 条），未作为契约基线，也未执行。
- **与既定约定的关系**：`server/RailroaderRV/agent.md:7` 约定"模块之间按既定接口直接协作，不添加针对其他模块接口的验证、防护、兼容或迁移代码"。本报告推荐的"应提供接口"全部是**收敛字段形状依赖**（把行为放到所有者一侧），不新增跨模块校验、不改变现有校验强度、不引入兼容/回退分支；反过来，凡加 getter 不能隐藏可变性、或调用点唯一、或本就是公开数据合同者，均判为"接口收益低于直接访问/登记"，与上述约定一致。

## 结论摘要

1. **最严重的跨模块耦合是 `RV.Server.isGenerationTransactionActive` 这条悬空接口**（7 处读取、0 处生产者，跨-3/跨-4 所在的 mutex 链）：`Core/RV_RailroaderServer_Sentinel.lua:150-163` 的汇合查询取不到 generation 一半，`installTransactionGate`（L197-209）因条件不满足恒返回 false。姊妹查询 `isWallReloadTransactionActive` 有完整发布机制（`WallReloadProtection/RV_RailroaderServer_WallReload.lua:246-273` + `RV_Server_Commands.lua:407-414` 调用安装器），generation 一半从未实现。
2. **第二严重的是 Power 读 mapping 记录里不存在的 `record.anchor`**（`Power/RV_UtilityPowerDevices.lua:235`）：两个调用点传入的都是持久 mapping 记录（`RV_UtilityServer.lua:227/314`），而该记录只持久化 `generated/locoId/generation/slotIndex/rvPosition/locoPosition/players`（`RVMapping/RV_RailroaderServer_EntryExit.lua:504-513`）。同仓正确写法就在 Water（`RV_UtilityWater_Objects.lua:37-39` 用 `RegionSlots.indexToAnchor`）。【事实】读取不存在的字段；【推断，条件：运行时记录确如源码】`scanAll`/`scanTick` 恒失败。
3. **Boundary 服务内部状态 `_states`/`_tick` 有两个跨模块只读探测点**（`BoundaryGuard/RV_RailroaderServer_BoundaryValidation.lua:67-73`、`DemolitionProtection/RV_BoundaryServer_Objects.lua:414/436/482/493`）。探测点**不能**复用既有访问器 `ctx.stateFor`，因为后者有创建副作用（`BoundaryGuard/RV_BoundaryServer_Geometry.lua:271-282`）——这是"接口收益低于直接访问"的典型证据，但同时也说明该只读语义值得一个正式名称。
4. **DemolitionProtection 把整个 builder ledger 表挂到 Boundary 命名空间**（`Objects.lua:411`），产生 3 处字段形状依赖；其中 `RVMapping/RV_RailroaderServer_EntryExit.lua:527-533` 是 **fail-closed**：ledger 字段或方法缺失会直接让 generation 的 mapping 提交失败。这是本次判定为"应提供接口"的最强一处。
5. **客户端与 Railroader 官方表之间的直读直写（`_boardPending`、`board.addForAnimal`、`AnimalContextMenu.doMenu`、`RR.TrainEntity.active`）无法用本地接口消除**：官方只暴露函数槽与内部记录表，包一层本地 façade 只会把同一批字段假设搬到另一个文件。判定：接口收益低于直接访问（证据：`GUI/RV_RailroaderContextMenu.lua:328-371,559-690`）。
6. **持久映射表 `mapData()` 是最大面积的共享可写结构**（12 个调用点跨 4 个包，`RVMapping/RV_RailroaderServer_Mapping.lua:29-31` 直接返回 `ModData.get` 活表），但它是存档 schema 合同本身：调用方必须就地改写（位置持久化 `Tick.lua:54-58`、原子表交换提交 `EntryExit.lua:541-543`），任何 getter 都只能再交出同一张表 → 收益低于直接访问。
7. **客户端 GUI 包内此前的互相读写已经收敛**：`roomOwnershipGuards` 现在是 `RV_ContextMenu_RoomOwnership.lua:5` 的文件局部表，`pendingFinalRelocation` 是 `RV_ContextMenu_Relocation.lua:22` 的文件局部变量，二者通过 `ctx` 导出的函数协作（`L285-291` ↔ `Relocation.lua:15-21`）。当前仅剩 `ctx.clientTick` 一个跨文件可变标量（`Relocation.lua:328` 写、`RoomOwnership.lua:189/273` 读）。
8. **整体判断**：全树共 25 条跨包访问、15 条包内互访；其中 4 条判为"应提供接口"、4 条"登记"、其余判为"接口收益低于直接访问"。耦合不是系统性失控——共享命名空间上的写入点大多有身份门与单一所有权；风险集中在"接口缺口 + 一处记录字段误用"两类，而不是"模块互相翻私有表"。

## 建议接口清单

> 只列判定为"应提供接口"的 4 项。均已确认不新增校验、不改变失败语义。

1. **`Boundary.transitionActive(identityKey) -> boolean`**（应对跨-3；可选覆盖内-1 的探测）
   - 使用方：`BoundaryGuard/RV_RailroaderServer_BoundaryValidation.lua:67-73`（替换 4 个条件）、可选 `BoundaryGuard/RV_BoundaryServer_Sweep.lua:126-127`。
   - 实现方：`BoundaryGuard/RV_BoundaryServer_Geometry.lua`（`_states` 的所有者）。内部逻辑与现有两处判定等价：`state.leaseToken` 是 string 且 `state.leaseUntil >= Boundary._tick`（现实现见 `BoundaryGuard/RV_BoundaryServer_Sweep.lua:48-56` 的 `leaseLive` 与 `BoundaryGuard/RV_RailroaderServer_BoundaryValidation.lua:69-73`）。
   - 改造范围：新增 1 个方法 + 1~2 处调用点；无装载顺序变更（两处都已持有 `Boundary`）。
   - 风险：低。附加收益：把"只读、不创建状态"与 `stateFor` 的创建语义区分开；若同时接受 `player` 或完整 identity 表（该调用点 L42-61 手上都有），还能顺带去掉 key 字符串格式这一约定依赖。

2. **`Boundary.pruneBuilderActions(tick) -> boolean` 与 `Boundary.invalidateBuilderActionsForGeneration(rvId, generation) -> boolean`**（应对跨-1/跨-4）
   - 使用方：`BoundaryGuard/RV_BoundaryServer_Sweep.lua:111-114`、`RVMapping/RV_RailroaderServer_EntryExit.lua:527-533`。
   - 实现方：`DemolitionProtection/RV_BoundaryServer_Objects.lua`（ledger 定义 L335、`prune` L337-346、`invalidateForGeneration` L348-363、发布点 L411）；ledger 表保持文件局部，命名空间上只暴露行为。
   - 改造范围：3 个文件、3 个调用点 + 发布点改写。
   - 风险：低，但必须**保留 EntryExit 的 fail-closed 语义**（方法缺失时仍返回 `C.INVALID_RV_DATA` 并拒绝提交映射，L528-532），不得放宽。

3. **`RV_UtilityPowerDevices.interior(anchor)` / `scanAll(identity, anchor, player)` / `scanTick(identity, anchor, player)`**（应对跨-13）
   - 使用方：`Core/RV_UtilityServer.lua:227`（`Devices.scanAll`）与 L314（`Devices.scanTick`）。

   - 改造范围：`Power/RV_UtilityPowerDevices.lua:234-288` + 2 个调用点。
   - 风险：中——`scanAll` 的失败语义当前同时是客户端 ACK 的失败原因（`RV_UtilityServer.lua:229-232` 把 `"RV interior coordinates are invalid"` 回给客户端），接口调整时需保持该返回值形状。

> 除上述 3 项外，跨包清单中没有任何一项需要新增接口：`RV.Server.isGenerationTransactionActive` 属"接口缺口"（见下节第 1 条），其余全部判为"收益低于直接访问"或"登记"。复核口径：仅当**加接口能真正隐藏可变性、或去掉字段形状/格式约定依赖**时才判"应提供接口"。

## 判定为"接口收益低于直接访问"的项及原因

- **跨-2（`Boundary._tick` ×4，DemolitionProtection）**：访问点全部落在同一文件；被读值与 `Core.getTick()` 恒等（[Sweep.lua:110](../../contents/mods/RailroaderRV/42/media/lua/server/RailroaderRV/BoundaryGuard/RV_BoundaryServer_Sweep.lua:110) 是唯一写者，其唯一调用方不传参）；加 getter 不能隐藏可变性（ledger `expires = Boundary._tick + 2`，L436 仍需读标量）。**登记**：字段改名会静默改变过期判定。
- **跨-5 / 跨-6（`ctx.pendingSerial`、`ctx.transitionSequence`）**：各自唯一读写点都在单一文件内；Core 侧同名本地变量在 ctx 构造后即死值（[RV_Server.lua:86/129](../../contents/mods/RailroaderRV/42/media/lua/server/RailroaderRV/Core/RV_Server.lua:86)、[RV_RailroaderServer.lua:91/106](../../contents/mods/RailroaderRV/42/media/lua/server/RailroaderRV/Core/RV_RailroaderServer.lua:91)）；自增语义要求写回，getter/setter 对不隐藏可变性。真正的收敛是所有权移动（改为使用方文件局部），不属于接口。
- **跨-7（`Adapter._ticks`）**：读取处已经写了回退 `Adapter._ticks or Core.getTick()`（[BoundaryValidation.lua:74](../../contents/mods/RailroaderRV/42/media/lua/server/RailroaderRV/BoundaryGuard/RV_RailroaderServer_BoundaryValidation.lua:74)），`Core.getTick()` 就是等价接口；再加一层 getter 是重复。
- **跨-12（`data.canBeWaterPiped`）**：vanilla 协议字段，vanilla 侧也读写它（[RV_UtilityCatalog.lua:87](../../contents/mods/RailroaderRV/42/media/lua/shared/RailroaderRV/Water/RV_UtilityCatalog.lua:87) 读、[RV_UtilityWater_Plumbing.lua:17/28](../../contents/mods/RailroaderRV/42/media/lua/server/RailroaderRV/Water/RV_UtilityWater_Plumbing.lua:17) 读写）；本地 façade 只会把同一字段假设搬到另一个文件，依赖不减。
- **跨-14/15/16（Railroader 官方表与函数槽）**：官方未提供 seat-transition / stale-gate / record lookup / menu 注册 API（依据本仓注释 L344-345、L659-661 与调用形状 L208-221、L480-481）；再包一层只是把字段假设移位；且这些访问已集中在单一 adapter 文件。
- **跨-17（`ctx.roomOwnershipGuards`）**：唯一消费者；表由 Core 创建但语义属 RoomOwnership；getter 不隐藏可变性。**登记**：所有权应收敛到 RoomOwnership 局部（非接口）。
- **跨-18（`ctx.serverTick`）**：接口（`Core.getTick()`）已存在且同值；字段缺失会立即报错，不会静默错值；跨包读只是同一 tick 的缓存。
- **跨-19（`ctx.railroader*Hook`）**：公开 setter 本身就是接口；ctx 字段是装载期传输通道；槽缺失走 fail-closed。
- **跨-20（`GenerationTransaction.current()` 的身份字段）**：已通过公开访问器取得；记录本身是"调用方直接写字段"的合同对象（[GenerationTransaction.lua:1-7](../../contents/mods/RailroaderRV/42/media/lua/server/RailroaderRV/Construction/RV_Server_GenerationTransaction.lua:1)），加二级 getter 只是再包一层；此处只比对 `rvId/generation` 两个字段。
- **跨-21（`constructionService` / `RV.Server.Construction`）**：同一对象两条发布路径，且 facade 路径无树内读者；需要的是去重登记，不是接口。
- **跨-22（`mapData()` 活表）**：12 个调用点跨 4 个包，但该表就是存档 schema 合同；调用方必须就地改写（`Tick.lua:54-58`）或做原子表交换提交（`EntryExit.lua:541-543`），任何 getter 都只能再交出同一张表；读侧已有 `validMappingRecord` 统一门（`Mapping.lua:126-132`）。
- **跨-23/24（`record.power` / `record.water` / 快照子表）**：Store 定义记录形状，Power 与 Water 各自独占一半（grep 复核：Power 只写 `record.power`，Water 只写 `record.water`）；快照类读取是深拷贝 value 对象（`Store.lua:147-161`）。
- **跨-25（`boundary.managed/shellEdges`、`bounds.anchor` 等）**：由 slotIndex + 编译模板纯函数派生的公开几何视图（[RV_Server_RecordValidation.lua:29-34](../../contents/mods/RailroaderRV/42/media/lua/server/RailroaderRV/RVMapping/RV_Server_RecordValidation.lua:29) 明文声明）；表即数据合同。
- **内-1（`_states`/`_tick` 同包）**：`_states` 单写所有者 + `_tick` 单标量；`Sweep.lua:126` 的探测**故意**不用 `ctx.stateFor`，因为后者会创建状态条目（[Geometry.lua:275-277](../../contents/mods/RailroaderRV/42/media/lua/server/RailroaderRV/BoundaryGuard/RV_BoundaryServer_Geometry.lua:275)）——提取成接口会改变"不创建状态"的语义。
- **内-3（事务记录字段直写）**：见上表理由；此外提取会改变异常/失败语义（`RV_Construction.lua:53-55`、`GenerationFlow.lua:114` 以 error 表达违约），与本仓"让错误按正常游戏异常抛出"的约定冲突。
- **内-4 / 内-5 / 内-8 / 内-12（ctx 装配协议与 clientTick）**：写入的都是模块自己的导出或单 writer 标量；这就是本仓的模块装配方式。

## 接口缺口与静态发现

1. **`RV.Server.isGenerationTransactionActive` 无生产者（源码事实）**：全树检索命中 7 处，**全部是读取/类型探测**，分布在 3 个文件：`Core/RV_RailroaderServer_Sentinel.lua:153`、`:157`、`:201`、`Core/RV_UtilityServer.lua:73`、`:74`、`WallReloadProtection/RV_WallReloadProtection.lua:456`、`:460`。全树不存在 `function RV.Server.isGenerationTransactionActive` 或 `RV.Server.isGenerationTransactionActive = ...`（`RV.Server` 上的写入点仅：`RV_Server.lua:96/99/138/139`、`RV_Server_Commands.lua:266/298/418`、`RV_Server_RecordValidation.lua:74/78/82/86/98/102/130/159`、`RV_Server_GenerationBuild.lua:176`、`RV_RailroaderServer_WallReload.lua:256`）。对照：姊妹查询 `isWallReloadTransactionActive` 有完整发布链（`RV_RailroaderServer_WallReload.lua:246-258` 定义、L265-271 `installWallReload` 发布，`RV_Server_Commands.lua:407-414` 在 facade 就绪后二次调用安装器）。generation 的真实状态存在于 `Construction/RV_Server_GenerationTransaction.lua:37-39`（`api.isActive`），经 `ctx.GenerationTransaction`（`RV_Server.lua:122`）注入，但未转发到 `RV.Server`。
   **条件性推断（未运行，触发条件＝运行时确实无外部/调试侧提供该函数）**：`Sentinel.serverTransactionMutexStatus` 恒走 `nil, nil, reason` 分支（L153-155）→ `wallReloadTransactionBlocks` 恒返回 `true`（L171-173）→ Enter/Exit 全被拒；`installTransactionGate` 恒返回 false（L201-203）→ `COMMAND_RV_ENTER/EXIT` 的 handler 不注册（`RV_Server_Commands.lua:411-414` 只打印未安装）；`BoundaryValidation` 的 `transactionStateValid` 恒 false（L64-66）→ `validatePlayer` 恒返回 nil（L86-88）→ 边界守卫不纠正任何玩家；`WallReloadProtection.begin` 恒失败（L456-458）；`UtilityServer.serviceBusy` 直接跳过 generation 一半（L73-77），与 Sentinel 的 fail-closed 口径不一致（**不许**通过放宽任一侧来消除差异）。
2. **`RV.Server.Construction` 无树内读者（源码事实）**：唯一命中是写入点 `Construction/RV_Server_GenerationBuild.lua:176`；同对象另有 `ctx.constructionService`（L174）由 `GenerationFlow.lua:187` 使用。重复发布，建议二选一。
3. **water tag 的 `slotIndex` 读写在服务端不对称（源码事实）**：写入 `Water/RV_UtilityWater_Objects.lua:147`；读取仅 `shared/Water/RV_UtilityCatalog.lua:41`（`readSinkIdentity`）→ 客户端 `GUI/RV_UtilityContextMenu.lua:110-112` 用它与本地推导的 slot 比较。服务端 `Catalog.isCurrentWaterSink`（L53-64）只比较 `rvId/generation`，`mappingRecord` 形参仅被类型检查（L57）而字段从未读取——即 tag 里的 `slotIndex` 在服务端从未与当前 slot 分配比对。是否构成缺陷需产品/运行时判断，本报告只登记事实。
4. **`RV_UtilityPowerDevices.interior` 的失败会被当作客户端 ACK 原因（源码事实）**：`scanAll` 返回 `false,"RV interior coordinates are invalid"` 时，`Core/RV_UtilityServer.lua:229-232` 直接把它作为 `acknowledge(..., false, scanReason)` 的 reason 下发，因此跨-13 的字段误用会以稳定字符串出现在客户端。
5. **`Devices.scanTick` 的返回值无人消费（源码事实）**：`RV_UtilityServer.lua:314` 忽略 `scanTick` 的返回值，因此即使它因 `record.anchor` 缺失而恒返回 false（L276），tick 路径也不会报错——这解释了为什么该缺陷只在 `OP_REFRESH_DEVICES` 路径可见。
6. **`tests/test_rv_server.py` 不是本期接口基线（源码事实，3 处已复核的不一致）**：L1891 要求源码存在 `function RV.Server.isGenerationTransactionActive`（当前不存在）；L1892 要求已从树中移除的 `isRoofRefreshTransactionActive`；L1041 断言 Sweep 必须保留 `local state = Boundary._states[id.key]`（即静态锁定内-1 的内部访问）；L1386 断言 `if old then old._boardPending` 不存在，而当前 `RV_RailroaderContextMenu.lua:367` 正是该写法。故本报告未把它当作契约依据，也未运行它。
7. **玩家身份 key 格式是事实上的跨包约定（源码事实）**：`BoundaryGuard/RV_BoundaryServer_Geometry.lua:77-78`、`BoundaryGuard/RV_RailroaderServer_BoundaryValidation.lua:55/59`、`WallReloadProtection/RV_RailroaderServer_WallReload.lua:91` 各自拼 `tostring(onlineId)..":"..name`；`Common/RV_Common.lua:80-90` 另有长度前缀版 `identityKey`（`RV_ServerUtil.lua:46` 导出，Power 用于 `rvId|generation` 缓存键，`RV_UtilityPowerDevices.lua:191` 等 8 处），两者格式不同、用途不同。跨-3 的接口若改为接收完整 identity 表，可一并去掉这里的格式约定依赖（属建议，不是本期改动）。
