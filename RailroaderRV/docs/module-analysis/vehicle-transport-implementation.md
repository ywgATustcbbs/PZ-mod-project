# BX40 平车与真实车辆运输

本文记录当前源码中的装卸数据流、状态范围和已知视觉限制。它是静态实现说明，不构成实际游戏或联机验收。

## 装卸请求与容量

- 仅未绑定为 RV 的 BX40 可转换为视觉平车。装载或卸载每次都要求玩家可检索的 inventory 中带有 RailroaderRV.LoadingRamp；跳板不会消耗。
- 客户端发送 Railroader unit 的稳定 ID 与车辆稳定 ID，或已分配的 cargo ID。请求不携带可信坐标或车辆状态。服务端按当前世界重新解析玩家、平车和车辆，并验证范围、楼层、加载状态、乘员/towing 状态、容量与目标车辆状态。
- 容量按 VehicleScript 的缩放车长计算，每 0.5 米为一段；车辆段数和相邻间隔段数合计不能超过 28。接受装载后，服务端按 14 米甲板布局分配车间和首尾空隙。
- 服务端在 ModData 中保存平车及货物清单；客户端只收到用于显示的 cargo ID、车型、中心偏移、状态摘要和视觉数据。

## 状态与物品

装车时服务端先保存公开 API 可往返的车辆和当前安装部件状态，并处理车辆本体、部件容器、点火钥匙及设备介质物品，再删除源 BaseVehicle 并提交货物记录。卸车时服务端在合法位置创建新的 BaseVehicle，恢复快照所包含的公开状态，再从平车清单移除该货物。状态与物品处理由服务端拥有。

原车 ID 不会保留：卸车创建的是新 BaseVehicle。里程、引擎累计运行时间等没有可往返公开接口的私有状态不会进入快照；依赖原 vehicle ID 的其他模组可能受影响。本文不承诺所有第三方部件状态都能按原车逐项复原。

## 客户端视觉

平车和货车模型由客户端装饰实体呈现，不会在服务端额外创建真实 BaseVehicle。视觉使用当前车辆脚本与部件声明的车型模型和当前车身 skin；它不包含原生逐模型显隐、材质/损伤与玻璃层、骨骼动画或车轮实时转向和旋转。

Model.ignoreVehicleScale 没有 Lua 可读接口，依赖该标志的附件比例可能不同。第三方车型的 mesh 原点或 offset 若与当前布局不一致，也会出现位置或比例差异；不含车型专用偏移补丁。

## 条件性失败撤销边界

以下是当前源码调用顺序的静态事实，不表示相应 native exception 已复现或必然发生：

- `dropContainerItems` 逐项从车辆容器移除物品、同步移除，再将物品放到世界格子。该序列没有对应的逆向操作；若过程中抛出异常，已处理物品不会由这条调用路径放回原容器。
- `Placement.spawn` 用保护调用包住 `State.restore`，恢复失败时会移除刚创建的车辆；随后执行的 `markVehicleStateForClients` 在该保护调用之外。卸车调用方只有在 `Placement.spawn` 返回成功后才从 cargo 清单移除记录。若后续同步调用抛出 native exception，函数不会返回成功，cargo 移除分支也不会执行；当前没有运行时证据证明该条件实际发生。

## 验收边界

源码与离线检查不替代实际装卸验收。实际运行时验证只能通过项目根目录的一键整体入口 python testserver/run_test.py，需同时启动可见服务器控制台和常规客户端；不可拆开启动客户端或服务器。本文不记录测试通过数，也不把未执行测试描述为通过。
