# RailroaderRVTest

RailroaderRVTest 是 Railroader RV 的内部技术验证包，不承诺对外功能。Lua 命名空间为
RailroaderRV；ModData 使用包级统一 schema 版本，处理规则见“Schema 与模块接口”。

## 重构草案

当前模块边界、接口与生成流程见[房车重构设计说明](REFACTOR_DESIGN.md)。

## 设计与安全边界

路线和房屋由服务端按需程序化生成，不内置地图。客户端只提交操作意图；服务端验证玩家、
权限、请求阶段和当前存档身份，负责世界修改、同步与失败回滚。

生成候选区从默认锚点 (20050,2050,0) 开始，按 5 行（Y）×20 列（X）排列；每格为一个
半开区间 100×100 管理区域，首格 x=[20000,20100)、y=[2000,2100)。服务端只从当前
Mapping 未占用的格子中按行优先顺序分配。Mapping 持久记录保存 slotIndex，anchor 与范围按
slotIndex 派生。生成先将客户端和服务器移到由所选布局中心派生的 staging 位置，再等待目标 IsoCell
可用并校验坐标；加载等待期间不做任何世界修改，也不要求预先加载完整
100×100 基面或上层 square。清理遍历
管理范围，只处理当前 cell 已有的 square，缺失 square 会跳过。Construction 在首次世界修改前
检查全部已加载目标 square；由于无法完整快照并恢复既有对象，目标范围内有对象或旧代际没有
完整 undo 快照时会 fail closed。生成只在固定模板对象的宿主 square 创建对象，缺失的宿主 square
按需创建；不铺整片金属地板，也不铺满空白格。完成生成后再 FinalRelocate 到该 RV 入口中心；首格的 FinalRelocate 点为
`(20050.5,2050.5,0)`，其他格按该格 anchor 平移。事务失败时回滚只处理本次 generation 创建的对象；
回滚失败会保留失败状态并拒绝盲目重试。矩阵空闲只表示 Mapping 未占用，不代表地图区域为空。
生成时客户端以“正在生成房车”提示等待。临时 staging 点由当前管理区中心计算：
`managedOriginX+floor(width/2)`、`managedOriginY+floor(height/2)`、`-15`。`-15` 是只存在于进程内存中的无状态 relocation sentinel；
服务端只用当前 Mapping 及由槽位派生的模板边界重新解析该位置，不把它持久化成玩家坐标，也不恢复原坐标。

房车模板来自 2026-09-25 服务端日志，保留了 357 个原始对象的坐标、对象类、名称、sprite、
朝向及捕获状态。捕获数据中的 50 处栅栏原有墙体衬层，其中 4 个不在房车边界上的衬层已移除；
其余 46 处真实边界位置上的 47 个木墙对象只在客户端隐藏；(2,2,0) 有两面同向墙。
墙体碰撞仍由服务端保留。
隐形墙现用于围住可活动区域，角落不再放独立隐形障碍物；西北角同时有北墙和西墙，另有四段角落隐形墙补齐边界缺口；当前共 412 个模板对象。玩家活动范围为 6×23 格；驾驶室内部 x=-4..1、y=-2..1 的 z0 格允许
建造和拆除，驾驶室上方车壳仍受模板保护。其余区域不允许建造。服务端每 10 tick 对
100×100 管理范围内的玩家采样，以玩家为中心将 3×3 XY 坐标去重排入共享的有界恢复队列。
每 tick 通常检查一个 XY 坐标；积压超过阈值时预算增至 2 或 4 个，并核对该坐标的受管 Z 层。
没有匹配在线玩家的队列项会出队丢弃；卸载或缺失的格不会强制加载。外部玩家物品和归属不明对象保留。
模板对象在非驾驶室格被拆除后，会在玩家接近并处理到该坐标时补回；驾驶室 z0 不自动
恢复。上层按捕获内容生成，不补齐空白格。实际边界 ledger 记录 59 条捕获墙边；西北角
由北墙和西墙组成，另新增四段隐形墙补齐活动区域边界缺口。移动许可按模板 walkAabbs 判定，
建造许可按 buildCells 判定；服务端边界守卫使用当前映射和玩家位置。

三条机制使用不同名称。**边界守卫（BoundaryGuard）**按服务端权威位置和 RV AABB 跟踪玩家，
并将越出管理范围的玩家送回已验证的 RV 入口位置。**模板保护修复（TemplateProtectionRepair）**
检查并恢复当前 RV 模板中受保护的对象；对象清理仍要求当前身份和模板归属明确。**屋顶刷新
（RoofRefresh）**在进入房车和重连路径上按当前身份尝试刷新房间与屋顶元数据；刷新时可临时
添加并移除未标记地板，保留模板地板。**墙体重载（WallReloadProtection）**处理特定外墙移除
后的独立流程：服务端捕获当前在场成员，协调临时远移、chunk 周期及逐人返回；客户端异步
传送完成后用 token ACK 推进阶段。客户端不提交可信坐标。

## Schema 与模块接口

全包使用 Lua 中集中声明的单一 schema 版本号，并保存到 ModData。启动时只比较一次：匹配时继续，
不匹配或缺失时发出警告但继续运行。各模块默认 ModData 与接口符合当前定义，不增加重复版本检查、
结构防护、接口校验、兼容、迁移或回退分支。用户承诺不使用旧存档；运行错误由游戏正常抛出，
之后由人工或 agent 排查是否与 schema 版本有关。

## 房车虚拟供电

每个 RV generation 在 UtilityStore 中独立保存虚拟汽油、铅酸电池组、荷电量、充放功率、
充电器/逆变器效率和结算时间。新建 RV 的虚拟燃油为 0 L、电池为空；世界重启不补算离线耗电。
原版 generator 只作为实际供电总开关：每游戏小时补满原版油量并修复 condition，原版油耗不进入
虚拟能源账本。虚拟发电按 1250 Wh/L 和 5000 W 额定功率结算；虚拟电池无电时关闭原版代理，
停止后需要电池达到 5% 才会重新开启。

玩家可添加/拆除/更换 `Base.CarBattery` 系列电池；服务端记录 condition 与充电量并移除实体，
拆除时重新创建物品。电池使用持久递增 ID，删除后新增不会与现有电池重复。低耐久电池的容量/充电功率采用抛物线下降，放电功率
采用平方下降。充电器和逆变器可通过配方制作，制作时读取 Electrical 等级并进行一次随机浮动；
结果存入物品 0–1000 condition，安装后效率固定。

设备发现和状态刷新分离：服务端每 10 tick 扫描 20 个内部 square，缓存只存坐标、类型、sprite、
额定功率和上次采样状态，不持有 IsoObject 引用。每十分钟先按旧采样负载结算，再读取当前设备状态；
进入 RV 后刷新一次，退出传送前结算一次。管理面板的“刷新用电设备”会完整扫描并刷新状态。
第一版状态适配支持灯、收音机/电视、冰箱/冷冻柜、洗衣机/干衣机、组合/堆叠洗烘机、炉灶和微波炉；
组合洗烘机按 washer/dryer 模式、堆叠洗烘机按两个独立开关计入负载。无法可靠
识别的 powered 对象忽略并写调试日志。扫描延迟、十分钟采样和区块卸载造成的账单误差属于已接受限制。
当前目标源码/API未提供可确认的“豪华烤箱”对象标记，因此这类 IsoStove 暂按普通炉灶 3000 W
计费；4000 W 配置值已集中保留，待明确对象标识后再启用。

RV 生成时仍在捕获模板的“发”区创建并标记原版 generator；缺失时沿用现有入口重建检查。
模板家具由捕获模板的生成路径创建，不在供电操作中改写。

## 验证状态

本包包含捕获模板生成、边界与建造审计、屋顶刷新和虚拟供电；水系统尚未完成，不在本次代码审计范围。
源码检查、Lua 语法与配置解析不能替代游戏内联机验证。本轮仅完成静态审查，未运行一键测试或联机验收。

2026-09-15 的历史人工测试曾报告拆墙、进出和补墙成功，但东/南墙格可建地板、东墙格可建
北墙仍待未来实机复核。当前源码包含相应 host 处理，尚无实机证据确认问题已解决。后续
人工测试不要要求用户提供客户端界面无法显示的实际坐标。

## 源包与导航

本地源包根目录为 RailroaderRVTest/，模组目录为
contents/mods/RailroaderRVTest/42/；media/lua/client/ 放客户端菜单与表现，
media/lua/server/ 放服务端玩法和世界操作，media/lua/shared/ 放共享契约；
tests/ 放静态检查。

Lua 实现按职责归入模块目录：客户端菜单和表现位于 `client/RailroaderRV/GUI/`；共享的
`Common/`、`RoomTemplate/`、`RVMapping/`、`Water/` 和 `Power/` 提供对应数据定义；服务端
`Core/`、`Common/`、`Construction/`、`RVMapping/`、`BoundaryGuard/`、`RoofRefresh/`、
`DemolitionProtection/`、`TemplateRecovery/`、`RoomOwnership/`、`WallReloadProtection/`、`Power/` 和 `Water/` 分别持有服务端职责。
静态检查直接读取这些模块文件，
并检查模块归属。模块间按现有接口直接协作，不添加接口校验、防护、兼容或迁移分支。

照明灯依赖运行时启用的 BuildingCraft（Workshop ID 3459887404）提供灯具图集和 tile
definition；本包不复制其资源。workshop.txt 有意留空 Workshop ID，发布前由 Workshop
流程分配。游戏基线只以根目录
game-decompiled/42.21.0/metadata.txt 为事实源，本 README 不重复版本数字。
本包使用其自建房电灯开关1（`BuildingCraft_Light_17`）；服务端生成前会检查 tile 的
`attachedW` 引擎标记，避免把同图集的普通装饰物当成玩家房屋灯开关。
