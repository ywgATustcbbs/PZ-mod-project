# RailroaderRV runtime test entry

- Runtime acceptance has one entry point: run python testserver/run_test.py directly from the project root. Do not run a preflight first, and do not start the client or server separately.
- The launcher stages the local RailroaderRV and BuildingCraft mods, starts the server with the selected cache profile, opens a visible server console, and launches the regular game client. The agent starts the launcher; after the client opens, the user performs in-game actions and reports observations.
- Workshop Railroader is the default source. Use python testserver/run_test.py --railroader-build preview to select the local preview source in Railroader-prerelease/railroader_pz_mod. Preview files are read-only and are copied into the selected test cache.
- Workshop defaults use the Z:/RailroaderRVCache server and client caches. Preview defaults use testserver/runtime/preview/server and testserver/runtime/preview/client. Keep the two modes' caches separate. In preview mode, custom --server-cache and --client-cache paths are base paths; the launcher adds a preview subdirectory.
- The launcher changes only Mods and WorkshopItems in the selected Server/test.ini and preserves other options. It does not reset saved worlds, player data, admin permissions, or SandboxVars. Keep any server-cache data that must survive outside a volatile Workshop RAM disk.
- The Workshop client cache may use a volatile Z: RAM disk. The launcher does not copy its cache back or automatically delete it. With the default preview caches, saves, logs, settings, and staged mods stay under testserver/runtime/preview; custom cache paths change the server/client cache locations.
- See run_test.py for the current source IDs, cache mechanics, and supported options; this document records the required runtime workflow without duplicating those frequently changing values.
