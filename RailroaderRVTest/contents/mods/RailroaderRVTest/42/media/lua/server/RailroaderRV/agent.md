# RailroaderRV server Lua

- `Core/` owns the server facade, command/event routing, and the Railroader adapter entry point. `Construction/` owns generation validation, staging, sparse cleanup, captured-object build, ACK handling, and failure handling without world rollback.
- `Common/` owns server world, the single Lua-declared schema version, ModData persistence, utility, and shared domain helpers. The schema version is checked once at mod startup; a mismatch only warns and does not block operation. `RVMapping/` owns current RV records and Railroader entry/exit. `BoundaryGuard/` owns the authoritative AABB guard and transition leases.
- `RoofRefresh/` owns the template-driven roof/room recalculation only. `WallReloadProtection/` owns the exterior-wall reload operation that moves every authoritative player out of an RV and back, `RoomOwnership/` owns the room-ownership guards. `DemolitionProtection/` owns shell-wall attribution. `TemplateRecovery/` owns current-template repair. `Power/` and `Water/` contain their respective server services.
- Generation waits at staging until every base square in the managed clear bounds is visible; cleanup starts only after this full-scope check passes. Cleanup walks the managed bounds and clears objects in its scope without preserving them for later restoration. Build creates objects only at current template-object hosts, materializing sparse upper host squares on demand; it does not create empty base-plane squares. The first required full RoomDef scan runs after the captured-object pass and before final relocation. A failed generation leaves world changes in place; when no mapping exists, the next attempt clears the managed bounds and starts generation again. The mapping is committed only after creation, utility initialization, and final relocation have completed.
- Keep world changes authoritative on the server and accept client intent only. Runtime code assumes persisted data and module interfaces match their current definitions; do not add repeated schema checks or inter-module interface guards, compatibility, or migration paths. Let errors surface as normal game exceptions for later diagnosis.
- Implementation ownership stays with the file under its module directory; no flat forwarding entries sit beside these folders.
