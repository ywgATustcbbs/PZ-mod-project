# RailroaderRV 1.0

RailroaderRV 是本项目唯一维护的房车模组目标。模组正式名称、包 ID、Lua 命名空间和本地源包目录均为 RailroaderRV。产品版本与 ModData schema 版本独立；schema 只在 Lua 中集中声明，本文不重复其数值。

## 功能范围

- 房车内部由服务端按需程序化生成，不内置地图；只在目标区域已加载后执行生成。
- 支持 Railroader 的 loco、car_box 与 car_bx40 物理 unit。每个 unit 保留独立稳定 mapping；car_box 与 car_bx40 保留各自 kind，但共用箱车模板类别。
- 玩家可进入房车，在允许的区域建造、布置和管理水电设施，也可按当前 mapping 将房车设为安全屋。
- 未绑定为 RV 的 BX40 可转换为视觉平车，用于运输真实车辆。
- 模组声明依赖 Railroader。

## 服务端权威与路线生成

客户端提交操作意图和所需对象标识。客户端不提交可信坐标、权限、车辆状态或世界状态。服务端按当前玩家、角色能力、距离、目标区域、对象身份、当前世界状态和请求阶段验证后执行世界修改、同步与失败处理。

生成从服务端分配的管理区域开始。服务端在目标区域完成加载检查前不清理或构建；客户端只执行服务端选择的异步移动步骤，并在服务端需要时用 ACK 报告完成。Mapping 在生成和最终移动阶段成功后提交。项目采用游戏提供的可靠有序网络传输，不为丢包、重复或乱序另加协议；只有服务端后续确实依赖客户端异步操作时才等待 ACK 或超时。

生成事务只使用进程内状态，没有持久回滚账本。当前生成失败中止（包括 WAIT_FINAL 截止时间超时）会回送在线玩家、关闭边界 lease 并释放事务，但不撤销已经产生的世界对象变更；下一次没有 mapping 的请求会先完整清理管理区再生成。这与根目录 agents.md 的失败回滚要求不一致，是尚未解决的契约差异。此为静态源码事实，未作运行时复现或修复。实际联机验收仍须按下方唯一入口执行。

## 车辆与房车交互

Railroader 每个物理 unit 与一个 RV mapping 对应；挂接或摘下其他车辆不改变该 unit 的稳定 ID。机车交互使用 Railroader 提供的菜单/API；箱车入口从游戏世界目标解析当前 unit。服务端仍重新验证单位和玩家位置。完成交互所需的公开几何或当前视图不可用时，操作会停止，不以缺省 pose 或历史坐标补算。

机车和箱车拥有各自的进出规则。机车退出按 Railroader 提供的座位选择规则处理；没有可用座位时拒绝退出。箱车没有座位，进入/退出使用该 unit 的 mapping 和服务端权威位置。房车安全屋仅覆盖对应驾驶室区域，沿用游戏原生安全屋行为。

未绑定为 RV 的 BX40 可用跳板装载或卸载车辆。装卸请求只带稳定 unit ID 与车辆 ID 或 cargo ID；服务端重新检查玩家、车辆、范围、加载状态、容量和当前车辆状态。跳板每次操作都要在玩家可检索的库存中，且不会被消耗。容量按车辆脚本长度以 0.5 米分段计算，连同车辆间隔不得超过 28 段，车间与首尾空隙再按现有 14 米甲板布局安排。

平车上的载车是客户端视觉实体，不是保留在世界中的原 BaseVehicle。装车时服务端保存公开状态、处理源车物品后删除源车；卸车时创建新的 BaseVehicle 并恢复已保存状态。游戏不允许 Lua 保留原 vehicle ID；里程、引擎累计运行时间等无可往返公开接口的私有状态不会进入快照。视觉内容保留静态车型模型与当前车身 skin，不重现原生逐部件显隐、材质/损伤层、玻璃层、骨骼动画或车轮实时转向和旋转。Model.ignoreVehicleScale 没有 Lua 可读接口，第三方车型的 mesh 原点或 offset 也可能造成比例与位置差异；依赖原 vehicle ID 的其他模组可能受影响。装卸的条件性撤销边界见[车辆运输说明](docs/module-analysis/vehicle-transport-implementation.md)。

## 建筑、模板与开发工具

机车模板将通行、禁止进入和可建造区域分开。沙盒选项可控制新生成的 loco 是否开放机电区域建造；既有 mapping 继续使用其记录的模板。箱车使用独立模板，不受该选项影响。模板保护、边界守卫、拆墙保护、房间所有权、屋顶刷新和墙体重载分别由对应服务端模块处理。

模板开发菜单由共享常量 `C.ENABLE_TEMPLATE_DEVELOPMENT` 控制，目前已关闭，服务端也会拒绝模板开发命令。开启时，玩家角色仍须具有 `UseDebugContextMenu` 能力；开发菜单可为 Railroader 守车 `car_cb` 新建开发空间、编辑已注册模板并输出捕获信息。捕获输出在服务端日志中，不自动改写 Lua 源码，也不写入 production mapping。守车生产模板保持注册，可用于新生成的独立守车。

## 水、电与屋顶设备

水和电在房车管理界面分开管理，并由服务端维护状态。

- 供水使用房车水箱和需电力的加压泵；最多安装两只 1,000 L 水箱。过滤器用于处理污染水和自动收集水，额定处理量为 5,000 L。可选抽水泵、雨水收集器分别记录泵送能力、容量和当前水量。手动加水按 40 L/min；小型与工业抽水泵分别按 40 L/min、20 W 和 200 L/min、100 W 运行。
- 房车电力按 UPS 模型运行：发电设备给电池充电，电器经逆变器从电池取电。系统支持燃油发电机、太阳能板、风力机、电池、充电器、逆变器、智能控制器和断路器，并展示设备状态与负载。最多安装 32 台发电设备、8 个油箱和 16 块电池。新 RV 的逻辑燃油和电池电量为零。
- 屋顶设备格由所选模板定义，不以屋顶外接矩形填满空格。每格最多放置一台发电或集水设备；太阳能板、风机与雨水收集器受邻格布局规则约束。服务端根据当前模板、状态和库存重新验证安装/拆除。

水箱、过滤器、水泵和发电设备是物品；屋顶放置使用模组记录的虚拟设备状态，不为这些设备创建对应的世界建筑。物品图标和配方纹理使用 RailroaderRV 前缀。

## 数据、schema 与模块边界

- 全包只有一个 Lua schema 版本常量，并写入 ModData。启动时集中比较；一致时继续，不一致或缺失时只报警并继续。
- 模组生成的模板、ModData、mapping、utility record 和进程内状态按可信数据处理。代码默认内部数据符合当前 schema；不为旧存档编写迁移、转换、兼容、回退或重复结构检查。理论上不可能的状态让游戏正常抛出异常。
- 模块按既定接口直接协作；不增加跨模块接口防护、兼容或迁移分支。源码静态审阅文档不代替游戏运行结果。
- RailroaderRV 源码和模块导航见[模块索引](docs/module-analysis/global-summary.md)；平车载车的完整状态与视觉边界见[车辆运输说明](docs/module-analysis/vehicle-transport-implementation.md)。

## 测试与验收

源码扫描、布局/数量断言和离线行为检查只能作为快速检查，不能替代实际运行时验收。唯一的一键整体运行时入口是从项目根目录直接运行 python testserver/run_test.py；它按脚本配置启动可见服务器控制台和常规游戏客户端。选择预览包时运行 python testserver/run_test.py --railroader-build preview。不要先做预检，也不要把客户端和服务器拆开启动。由 agent 启动脚本；客户端启动后，用户只负责连接、移动、点击等操作并观察反馈。

运行时验收的启动细节、缓存来源和独立路径见[testserver 使用说明](../testserver/agent.md)。本文不列离线测试通过数，也不把未执行的测试描述为通过。

## 项目目录导航

模组源包位于 RailroaderRV/contents/mods/RailroaderRV/42/：

- media/lua/client/：菜单、输入、客户端表现和操作意图。
- media/lua/server/：权威验证、生成、世界修改、同步、持久状态和服务端业务。
- media/lua/shared/：共享常量、布局、模板、物品定义和静态配置。

项目级目录与文件位于源包之外：RailroaderRV/tests/ 保存源码契约与离线行为检查；RailroaderRV/docs/module-analysis/ 保存模块职责索引和技术边界；Workshop 元数据位于 RailroaderRV/workshop.txt。测试和静态文档不等同于游戏内联机验收。

游戏基线、反编译元数据和相关版本数字只以根目录 game-decompiled/42.21.0/metadata.txt 为事实源；本 README 不重复基线版本。
